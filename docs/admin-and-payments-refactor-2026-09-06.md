# 관리자·티켓·결제 구조 정리 — 2026-09-06

## 완료 범위

1. 티켓·행사 관리
   - 티켓 조회에 행사 연결 정보를 포함하고, 연결된 티켓에서 해당 행사를 바로 연다.
   - 행사에 사용 중인 프로그램의 구형 전체 편집은 읽기 전용으로 표시한다. 일정·장소·조 변경은 행사 관리에서 수행한다.
   - 연결 티켓의 공개 상태는 별도 저장 경로로 변경한다. 이 경로는 공개 상태와 수정 시각만 갱신한다.
   - 독립 프로그램/샘플의 생성·편집은 유지한다. 실제로 호출되지 않던 ContentEditor, RecommendationAudienceEditor, NoticeEditor, StageCopyEditor와 오래된 참가자 편집/즉시 공개 UI를 제거했다. 다른 호출자가 사용할 수 있는 기존 서버 작업은 임의로 삭제하지 않았다.
   - 편집 UI, 일정 목록, 미리보기, 입력값 변환/타입을 `src/features/admin/tickets/`로 분리했다.

2. 관리자 메인
   - 회원 목록, 상세 정보, 운영 평가, 설문 내보내기를 `src/features/admin/profiles/`로 분리했다.
   - 각 관리 탭은 dynamic import로 처음 열 때 코드를 불러온다. 기존 탭 상태 보존 방식은 유지한다.

3. 사용자 홈·내 티켓
   - 티켓 목록, 카드, 신청 상세, 진행 안내, 도착 상태와 프로필 생성 화면을 독립 모듈로 분리했다.
   - 조회 캐시와 동시 요청 합치기는 `src/features/app/data/userTickets.ts`에서 담당한다. 계정/페이지별 구분을 유지하고, 잘못된 응답은 빈 목록으로 캐시하지 않는다.
   - 내 티켓 API는 인증 경계를 담당하고 `src/server/meetings/readUserTickets.ts`로 조회를 넘긴다.
   - DB 조회, 행사 관계, 티켓 표시·상태 계산을 별도 모듈로 분리했다.
   - 쓰이지 않던 기본 프로필 편집 폼과 이전 점수 계산 함수도 제거했다.

4. 결제·취소
   - 웹훅 경로는 수신·서명 검증·처리권 확보·재시도 응답을 담당한다.
   - `src/server/payments/`에서 결제자 찾기, 결제 정보 정규화, 멤버십 결제/취소, 일회권 결제/취소를 분리했다.
   - 중복 방지 키, 처리권 토큰, 요청 취소 신호와 기존 DB 공통 상태 변경 경로는 유지한다.
   - 이 작업은 구조 분리다. 멤버십 관련 여러 테이블을 하나의 새 트랜잭션으로 바꾸거나 결제 정책을 변경한 것은 아니다.

## 검증

- 기존 회귀 검증을 포함해 테스트 227개 통과.
- 새 검증: 계정/페이지별 조회 격리, 동시 새로고침 합치기, 잘못된 응답 및 네트워크 실패 후 재시도, API 인증 경계, 동시 웹훅 처리 컨텍스트 격리.
- 타입 검사와 운영 빌드 확인.
- 실제 운영 결제/취소 또는 참가자 데이터 변경은 실행하지 않았다. 브라우저 전체 운영 시나리오 검증은 별도다.
