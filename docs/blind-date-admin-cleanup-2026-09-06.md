# 블라인드 데이트 관리자 정리 — 2026-09-06

## 운영 흐름

- `데이트 만들기`에서 이름/전화번호로 참가자 두 명을 선택하고 시간·지역을 입력한다.
- 장소·주소·예약자명은 생성할 때 또는 상세 관리에서 입력한다.
- 생성 즉시 두 사람의 사이트에 초대장이 표시된다. 별도 메시지를 발송하지는 않는다.
- 진행 중 / 종료 기록 / 전체 목록과 검색으로 찾고 상세 관리에서 상태·응답·일정·장소를 수정한다.
- 응답 초기화는 기존처럼 확인 후 실행한다.

## 삭제한 기능

- 피드백을 전수 조회해 상호 후보를 계산하는 관리자 전용 로직과 후보 화면.
- 블라인드 데이트 템플릿 생성·수정·복제·삭제 API 및 화면.
- 템플릿 사진 업로드, 티켓 미리보기, 단계별 안내문 꾸미기, 고정 문자 복사 UI.
- 후보 계산 전용 타입 및 관련 모임/템플릿 추가 조회.

기존 구조는 후보를 자동 계산한 뒤 운영자가 생성 버튼을 누르는 방식이었다. 이번 변경은 그 후보 계산과 템플릿 기반 생성 경로를 제거한다. 참가자가 가능한 날짜를 선택하고 공통 일정을 정하는 사용자 기능은 유지한다.

## 유지하는 데이터/호환성

- 기존 초대장·응답·피드백·템플릿 DB 기록은 삭제하지 않는다. 기존 사용자 초대장의 템플릿 읽기는 계속 지원한다.
- 새 초대장은 nullable `template_id`를 null로 저장하고 사용자 화면의 기본 안내를 사용한다.
- 기존 DB의 `source_type=test`는 이미 운영자 직접 생성에 쓰던 값이며 새 수동 생성도 같은 경로를 사용한다. 사용자에게 표시되는 실제 초대장이며 테스트 전용 노출 필터는 없다.
- 다른 티켓 화면에서 사용하는 공용 이미지 업로드 API는 유지한다.
- 예약자명 강제 덮어쓰기를 제거했다. 미입력 시 사용자에게 `운영진 확인 중`으로 표시한다.
- 장소만 수정할 때 확정 날짜를 함께 재전송하지 않아 종료된 데이트가 일정 확정으로 되돌아가지 않게 했다.

## 코드 경계

- BlindDateAdminPanel: 데이터 로드·저장 및 화면 연결.
- blindDates/CreateBlindDateForm: 수동 생성.
- blindDates/BlindDateOfferList: 검색·기록 구분·상세 선택.
- blindDates/OfferControls: 일정·장소·응답 편집.
- admin/blind-dates/route: 관리자 인증과 생성·수정·조회.

추가 DB 마이그레이션은 없다. 앞선 행사 운영 통합 작업의 미적용 마이그레이션은 별도로 남아 있다. 이번 변경도 로컬 작업이며 운영 배포 및 push는 하지 않았다.

## 검증

템플릿 없는 생성, 동일 참가자 거부, 관리자 인증, 폐기 API 차단, 예약자명 저장, 후보 데이터 미조회 회귀 테스트를 추가했다. 브라우저에서 실제 생성/발송은 실행하지 않았다.
