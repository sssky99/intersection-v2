# 친구 초대 문자 연결

2026-09-08 기준. 기존 솔라피 키는 유지하고 웹사이트 전용 키를 생성했다.
만료: 2027-09-08 23:59:59 KST. 인증정보는 `.env.local`과 Netlify 환경변수에만 저장한다.

## 서버 설정

- `SOLAPI_API_KEY`
- `SOLAPI_API_SECRET`
- `SOLAPI_SENDER_NUMBER` (사전 인증한 발신번호)
- `FRIEND_INVITE_SITE_URL` (선택; 기본 `https://interv2.netlify.app`)

프런트엔드 공개 환경변수로 복사하지 않는다. 신규 배포 전까지 운영 사이트 코드는 바뀌지 않는다.

## 흐름과 사진 공개

번호 입력과 날짜 선택 단계에서는 사진을 조회하거나 문자를 보내지 않는다.
기존 신청 기록 저장 후 `/api/friend-invitations`에 신청 ID, 친구 번호, 동의 여부를 보낸다.
본인 소유 신청만 사용하며, 신청당 친구 한 명, 사용자당 24시간에 신규 초대 세 건으로 제한한다.
결제 대기 상태도 신청 기록으로 취급하므로 결제 화면 이동 전 초대 문자를 요청한다.
문자에는 초대 기록별 `/invite/{id}` 링크를 넣는다. 이 경로는 로그인·가입 중 초대를
쿠키로 보관하고 `/meetings?friendInvite={id}`로 연결한다. 로그인 후 수신 번호와 계정 번호,
발송 성공, 초대 마감, 발신자 신청 상태를 검증한다. 검증된 수신자는 날짜 선택을 건너뛰고
해당 모임 여정으로 바로 이동하며, 내 친구 자리에는 발신자 프로필 사진을 표시한다.
다른 번호의 계정에는 발신자 사진이나 모임 정보를 반환하지 않는다.

발송 요청은 재시도하지 않는다. 동일 신청의 반복 요청은 기존 초대 기록을 반환한다.
접수 성공은 `submitted`, 수신번호와 발신번호까지 일치하는 솔라피 상태 `4000`만 `sent`로 처리한다.
사진 조회 API는 로그인 사용자 소유 초대, 유효한 신청, `sent` 상태를 서버에서 확인한다.
관리자 여부나 클라이언트의 성공 플래그로 사진을 공개하지 않는다.
이전 `/api/dev/friend-profile` 경로는 항상 404를 반환한다.

초대장 여정 화면을 열면 발송 상태를 확인하고, 전송 중이면 5초 간격으로 최대 12회 확인한다.
재진입하면 다시 확인한다. 이 화면에만 친구 사진을 전달한다.
대상 번호의 회원이 없거나 사진이 없거나 중복 회원이 있으면 기본 아이콘을 유지한다.

## 불확실한 발송

타임아웃이나 발송 직후 저장 실패는 `unknown`으로 남긴다. 중복 발송 위험 때문에 자동 재전송하지 않는다.
솔라피 콘솔에서 `customFields.invitationId` 또는 그룹/메시지 기록을 대조한 후 운영자가 복구해야 한다.
`sending` 상태에서 프로세스가 종료된 경우에도 콘솔 확인 전 재발송하지 않는다.

## 검증

- 실제 솔라피 잔액 조회 200으로 새 키의 인증 확인 (문자 발송 없음).
- 발송 성공 판정/인증/타임아웃 중복 방지와 사진 접근 테스트.
- DB 예약 RPC를 트랜잭션 안에서 두 번 호출하여 중복 생성 방지 확인 후 롤백.
- 초대 테이블 RLS 활성화 및 anon/authenticated 직접 접근 차단 확인.
- 2026-09-08 승인된 별도 초대장 예시 문자 1건을 발송하고 솔라피 `4000` 전송 성공 확인.
  전송 전 기본 아이콘, 전송 후 초대자 사진과 무작위 멤버 사진 표시를 브라우저에서 확인했다.

초대 기록은 친구 번호와 신청 이벤트의 연결을 저장한다. 운영 조 편성 화면과 배정 알고리즘에서
이 기록을 읽어 동반 배정을 강제하는 작업은 별도이며, 이 변경은 조를 자동 편성하지 않는다.

## 별도 초대장 테스트

운영자가 명시적으로 요청한 예시 발송은 `friend_invitation_examples`에 따로 기록한다.
실제 신청 기록은 만들지 않는다. 무작위 UUID 링크는 만료 시간까지만 열리며,
운영 배포에서는 `/invite-example/{id}`를 차단한다. 이 예시 링크는 수신자가 로그인 없이
여정 디자인을 확인하는 용도이므로 실제 초대 수락/결제 기능은 제공하지 않는다.
발송 성공 확인 전에는 초대자의 사진을 읽거나 출력하지 않는다.
테스트 테이블은 RLS를 켜고 서비스 역할 외 접근을 차단한다.
Netlify `friend-invite-test` 분기 환경에만 필요한 서버 연결 정보를 별도로 설정한다.
