# 친구들과 추억들

## 현재 화면

- 하단 첫 번째 친구 탭 안에 친구들 / 추억들 탭을 둔다.
- 친구들은 최대 9명의 폴라로이드 보드이며 순위가 아니다.
- 친구 추가·삭제에는 수락이나 상대방 알림이 없다.
- 사진 구도와 자리 배치는 내 보드에만 적용한다.
- 사진에서 다음 모임 함께하기 → 일정 선택 → 초대 내용 확인으로 이동한다.
- 받은 친구 요청 대신 받은 모임 초대를 표시한다.
- 베이지와 먹색을 사용한다.

## 실제 연결

- 후보: 한국시간 오늘 기준 최근 **2개월(달력 월 기준)** 동안 같은 1차 조 또는 저장된 2차 조에 속했던 동성 멤버. 모임 **다음 날**부터 표시하고 최근 만난 날짜 순으로 정렬한다. 취소·노쇼·탈퇴 계정, 미공개/테스트 행사와 본인은 제외한다. 도착 상태가 미입력인 승인 참가자는 포함한다.
- 1차: 기존 확정 그룹의 참여 기록을 사용한다. 운영 그룹 티켓은 draft여도 부모 행사가 public/closed이고 그룹이 confirmed면 포함한다.
- 2차: 관리자 행사 화면의 `2차 조 기록`에서 같은 조의 멤버에게 같은 조 이름을 입력한다. 빈칸은 미참여. 저장은 한 트랜잭션으로 교체하고, 중복·다른 행사·취소·노쇼 멤버를 거부한다. 사용자에게 편성표는 노출하지 않는다. 예전 2차 기록은 입력된 행사만 반영되며 추측하지 않는다.
- 저장: 서버의 소유자 전용 9칸 보드. 전화번호를 클라이언트에 주지 않는다. 2개월이 지나도 이미 저장한 친구는 유지한다. 직접 삭제한 뒤 기간이 지나면 다시 후보에서 추가할 수 없다. 원 참여 기록이 취소/노쇼로 정정되거나 계정이 탈퇴되면 보드에서도 제외한다.
- 초대: 본인이 신청한 공개 행사 중 시작 24시간 전까지 선택할 수 있다. 실제 SMS는 확인 화면에서 `초대 문자 보내기`를 눌러야 전송한다. 서버가 친구 자격을 재검증하고 전화번호와 본문을 결정한다. 기존 솔라피 LMS와 개인별 `/invite/{id}` 링크를 사용한다.
- 기존 초대 제한을 유지한다: 신청 1건당 1명, 하루 최대 3건. 중복 예약 시 다시 보내지 않으며 불확실한 전송도 자동 재시도하지 않는다. API 접수(submitted)와 실제 배송(sent)을 구별한다.
- 받은 초대는 번호가 일치하는 본인에게만 표시하고 기존 초대 확인·신청 경로로 연결한다. 실제 함께 신청 관계는 기존 관리자 신청 명단에 표시되는 구조를 재사용한다.
- 개발 미리보기는 여전히 샘플만 사용하며 실제 저장·문자를 호출하지 않는다.

## 후속 연결 범위

- 추억들: 본인이 참여한 날짜별 앨범. 운영진이 현장에서 촬영하거나 참가자에게 받은 사진을 업로드하고, 해당 모임 참가자에게 제공한다.

추억들은 현재 빈 화면만 구현되어 있으며 업로드·앨범 조회는 미연결이다.

## 접근 제어 및 검증

새 테이블과 함수는 RLS를 켜고 클라이언트 역할의 권한을 회수했다. 인증된 서버 API가 본인 ID만 사용한다. 따라서 새 테이블의 RLS 정책 없음 안내는 의도된 서버 전용 설계다. SQL 회귀 테스트는 2개월 경계, 미래/당일 제외, 동성/조 검증, 저장 유지, 위조와 중복 거부, 원자적 2차 저장을 검증한다. 문자 테스트는 솔라피를 모의 처리하며 실제 고객 문자는 보내지 않는다.
