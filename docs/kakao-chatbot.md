회원 연결 스킬과 별도로 `CS 기본 안내 테스트` 스킬과 `CS 기본 안내` 블록을 추가했다.

- 테스트 서버: `https://kakao-cs-test--interv2.netlify.app/api/webhooks/kakao-cs`

- 카카오 블록: `6aa0ecde45fea95c7b43caf1`
- 봇: `6a659043fd013545b64506e9`

`KAKAO_CS_AI_ENABLED=true`일 때 GPT-5.6 Sol (`gpt-5.6-sol`, Responses API, reasoning none, store false)이 최근 대화와 검토한 CS 지침을 참고해 답한다. false이면 기존 FAQ 3개 응답으로 돌아간다. ‘구매 내역 확인하기’라는 운영자 정정 문구를 적용했다. 회원 조회, 환불·취소 처리, 운영자 알림·상담 자동 배정은 구현하지 않았다. 실제 처리 요청은 운영진 확인이 필요하다고 답하고 해당 세션 AI를 일시 중지한다.

### AI 서버와 남은 카카오 설정

운영자 요청으로 답변집 **5번 신청·참여 확정 여부와 9번 참가자 나이대·조 구성은 자동답변 제외**다. 모델이 `manual_topic=true`로 분류하면 생성한 내용 대신 고정된 운영진 확인 안내를 반환하고 `needs_operator=true`로 상담을 중지한다. 확정 기준/시점 및 연령대/성비/조원 구성에 관한 일반적인 질문과 문맥상 후속 질문도 포함한다.

제외 처리 검증: 관련 테스트 28개와 타입 검사 통과. 실제 GPT-5.6 호출에서도 ‘제 신청은 언제 확정되나요?’, ‘이번 모임은 몇 살쯤 오고 남녀 비율은 어떻게 돼요?’가 고정 안내와 needs_operator=true로 돌아왔다. ‘구독 해지는 어디서 하나요?’는 기존 ‘구매 내역 확인하기’ 안내를 유지했다.

- 코드: `lib/kakaoCsAi.ts`, `lib/kakaoCsConversation.ts`, `/api/webhooks/kakao-cs`.
- 환경 변수: `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `KAKAO_CS_SKILL_SECRET`, `KAKAO_CS_BOT_ID`, `KAKAO_CS_AI_ENABLED`. 키는 출력하거나 문서에 기록하지 않는다.
- 일반 스킬의 5초 제한 때문에 `userRequest.callbackUrl`이 필요하다. 즉시 `useCallback: true`를 반환하고 Next.js `after`에서 답변을 생성해 카카오에 돌려준다. 카카오 호스트만 허용하며 일회용 콜백은 불확실한 실패 후 재전송하지 않는다.
- 카카오 `CS 기본 안내`와 `폴백 블록`의 콜백을 활성화하고 폴백 응답을 `CS 기본 안내 테스트` 스킬 데이터로 저장했다. 기존 웰컴/회원 연결 안내 정리는 아직 남아 있다.
- Netlify CLI alias 배포의 실제 런타임 context는 `branch-deploy`다. 빌드 context인 deploy-preview와 별개이므로 AI 키/설정을 양쪽에 넣었다. 운영 context는 활성화하지 않았다.
- 카카오 관리자 봇테스트의 콜백 토큰은 실제 전송 검증에 사용할 수 없다. 개발 채널을 연결한 휴대폰 테스트가 필요하다.
- 테스트 서버에서만 `KAKAO_CS_ALLOW_DIRECT_TEST=true`와 인증된 `x-kakao-cs-test: true` 요청으로 동기 답변을 검사할 수 있다. 이 헤더를 카카오 스킬에 등록하지 않는다. 운영 활성화 전에는 해당 환경 변수를 false로 바꾼다.

### 대화 보관과 상담 중지

`20260909080757_kakao_cs_conversations.sql` 적용. 사용자 식별값을 HMAC 처리하고 전화번호 패턴을 마스킹한다. 서로 다른 사용자와 테스트/실제 세션을 분리하고 최근 12개 메시지만 모델에 전달한다. 마지막 활동에서 24시간이 지난 뒤 다시 문의하면 이전 문맥을 비운다. 이는 24시간 자동 삭제를 뜻하지 않는다. 보관 데이터 정기 삭제는 별도 운영 작업이다.

동일 콜백 중복, 동시 실행, 사용자별 하루 30회 초과 호출을 제한한다. 실제 처리 요청이나 콜백 전달 실패 시 `paused=true`가 된다. 운영진은 기존 카카오 상담창에서 직접 답하고, 재개가 필요하면 서버 관리자 권한으로 해당 세션의 paused를 해제해야 한다. 상담원 알림과 관리자용 재개 화면은 아직 없으므로 고객용 자동화 활성화 전에 운영 동선을 정해야 한다.

테이블과 RPC는 service_role 전용이며 일반 사용자 읽기/호출 권한을 차단했다. 보안 점검의 RLS 정책 없음 안내는 서버 전용 테이블이므로 의도된 상태다.

이름+번호 뒷자리만으로 개인 신청 정보를 공개하는 데에는 본인 확인이 충분하지 않으므로 CS 스킬은 기존 회원 연결 데이터를 사용하지 않는다. 개인화 조회는 별도 본인 확인을 구성한 뒤 추가한다.

테스트 배포는 운영 사이트 배포와 별개다. 운영 채널 연결·배포 전에는 실제 고객 자동 응답이 켜지지 않는다. 현재 봇의 운영/개발 채널은 연결되지 않은 상태로 확인했다. 상담원 전환, 폴백/웰컴의 기존 회원 연결 안내 정리, 운영 URL·인증 환경 설정을 완료한 뒤 고객용으로 배포해야 한다.

검증: AI·콜백 라우팅·DB 격리 관련 테스트 26개. 기존 정적 FAQ는 카카오 봇테스트에서도 ‘구독 해지 방법’이 `CS 기본 안내` 블록을 통해 돌아오는 것을 확인했다. AI 카카오 콜백 전송 성공과는 구별한다.

최종 테스트 배포: `6aa118188398ee135e6da85b`. 인증된 테스트 서버에 같은 합성 사용자로 4회 요청해 구독 해지 → ‘그럼 탈퇴만 하면요?’ 문맥 유지 → 환불 실제 처리 요청 → 상담 중지 안내를 확인했다. 응답 시간은 약 9.3초(첫 실행), 4.0초, 3.7초, 1.2초였다. 저장 메시지 6개, paused=true, 실행 잠금 해제 상태를 DB에서 확인했다. 타입 검사 통과. 실제 모델과 DB를 연결한 합성 대화로 별도 검증했다.

초기 1.5초 DB 제한은 테스트 서버 첫 실행에서 요청 잠금을 남길 수 있어 5초로 조정했다. 실제 카카오 요청은 DB 조회 전에 콜백 접수 응답을 반환하고 이후 저장/생성을 수행한다. 운영/개발 채널 연결 및 휴대폰 콜백 수신은 아직 검증하지 않았다.

공식 규격 참고: https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/make_skill

아래는 기존 회원 연결 스킬 문서다. 관리자에 저장되어 있던 인증 헤더는 오류 문구였으므로 작동하는 연결로 간주하면 안 된다. 이번 CS 작업에서 해당 스킬을 수정하거나 고객 대상으로 활성화하지 않았다.

## 목표

카카오 채널 1:1 채팅에서 사용자가 `이름 + 휴대폰 번호 뒤 4자리`를
입력하면 기존 Supabase 회원과 카카오 사용자 식별값을 연결하여 운영자가
참가자를 분류하고 문의를 확인할 수 있게 한다.

예시 입력:

```text
김서연 1234
```

## 서버 구성

- 스킬 URL: `/api/webhooks/kakao-chatbot`
- 인증 헤더: `x-kakao-skill-secret`
- 환경 변수: `KAKAO_CHATBOT_SKILL_SECRET`
- 연결 테이블: `public.kakao_channel_links`
- 연결 시도 기록: `public.kakao_channel_link_attempts`

카카오 챗봇 관리자센터의 스킬 설정에서 운영 사이트의 전체 URL과 인증
헤더를 등록한다. 예:

```text
https://<운영 도메인>/api/webhooks/kakao-chatbot
```

## 챗봇 블록

### 웰컴 블록

```text
안녕하세요, 교집합입니다.
신청 정보를 연결하려면 이름과 휴대폰 번호 뒤 4자리를 보내주세요.
예: 김서연 1234
```

### 회원 연결 블록

사용자 발화 전체를 스킬 서버로 전달하고 스킬 응답을 출력으로 사용한다.
별도의 엔티티 추출 없이 서버가 발화를 검증한다.

## 매칭 규칙

1. `profiles.name`이 정확히 일치해야 한다.
2. `profiles.phone_normalized`가 입력한 네 자리로 끝나야 한다.
3. `profile_completed = true`인 프로필만 대상으로 한다.
4. 정확히 한 명만 일치할 때 연결한다.
5. 한 회원과 한 카카오 봇 사용자는 각각 하나의 활성 연결만 가질 수 있다.
6. 0건, 다건, 기존 연결 충돌은 자동 연결하지 않고 시도 기록에 남긴다.

## 운영 안전장치

- Supabase service-role 키와 스킬 시크릿은 서버 환경 변수로만 관리한다.
- BuilderBotTest 요청은 형식만 확인하고 DB에 저장하지 않는다.
- 카카오 표시 이름은 발송 주소로 사용하지 않는다.
- 연결 후에는 저장된 Kakao 사용자 키를 사용한다.
- 현재 범위에서는 자동 메시지 발송이나 생성형 답변을 수행하지 않는다.
